# 终端不换行视图：第一版实施计划

## 状态

第一版已实现，待本地聚焦测试和手工验收。只实现当前窗格的临时不换行视图；模式开启期间冻结模拟器和 PTY 列数，避免窗口宽度变化触发重排。

## 一、目标与边界

| 编号 | 目标 |
|---|---|
| R1 | 不换行时，将 alacritty 的软折行链显示为一条逻辑行，显示长度不受视口宽度限制 |
| R2 | 切换后立即重建设定范围内的可见视图；已折行的历史输出也拼接 |
| R3 | 不换行期间横向 resize 不改变网格和 PTY 列数；切回自动换行后按当前视口恢复 |
| R4 | 横向滑杆使用本模式开启后曾经显示过的最大行宽；短行回到视口时不缩小 |
| R5 | 显示、排版和绘制只处理可见行及横向可见列，不遍历全部回滚历史 |

第一版约束：

- 开关仅作用于当前窗格，不持久化。
- 只拼接 `WRAPLINE` 软折行。程序主动输出的换行和被程序截断的内容不能还原。
- 链头已超出回滚上限时，只能显示仍保留的部分，不宣称恢复已淘汰内容。
- alt screen 始终使用原始物理视图，保留开关状态，退出后恢复。
- tmux 控制模式继续使用现有合成快照，不启用拼接。
- 不换行时取消纵向小数平滑滚动，按完整逻辑行滚动。
- 块选区支持当前视口；拖出视口时钳制到边缘，不扩展跨页块选区。
- 含终端图像的折行链保持物理行显示，第一版不重排图像高度。

## 二、总体结构

```text
PTY / SSH：不换行时冻结列数，自动换行时使用真实视口宽度
        ↓
alacritty：物理行 + WRAPLINE
        ↓ 同一把锁内取得足够物理行
物理快照：保留网格坐标、拼接元数据和实际窗口顶部
        ↓
DisplayView：命令折叠 + 软折行拼接
        ├─ 显示快照
        └─ DisplayMap：显示坐标 ⇄ 物理坐标
        ↓
TerminalElement：按横向可见列排版和绘制
```

自动换行且没有命令折叠时，`DisplayView` 直接返回物理快照和恒等映射。

## 三、必须先确定的合同

### 3.1 物理快照合同

在现有快照接口上增加窗口选项，并贯穿 `try_render_snapshot()`、`snapshot_with_display_offset()` 和 `TerminalSession`：

```rust
enum SnapshotWindow {
    Viewport,
    LogicalLines { count: usize },
}
```

要求：

- `Viewport` 保持现状。
- `LogicalLines` 返回请求数量的完整折行链（历史不足时除外），窗口顶部对齐链首，不得额外纳入下一条链；请求数量包含会被命令折叠隐藏的链，保证变换后填满视口。
- 后端按 `display_offset == 0` 自动选择底部锚定，否则使用顶部锚定。
- `display_offset` 保留用户滚动锚点，底部始终为 `0`；实际窗口顶部通过 `window_display_offset()` 从首行网格行号推导，两者不得混用。
- `TerminalSnapshot.rows` 继续表示视口行数；物理快照的 `lines.len()` 可以更大，显示快照的 `lines.len()` 为实际显示行数。
- 窗口计算、网格内容、选区和图形状态在同一把后端锁内取得。持续输出导致锁竞争时沿用现有延迟策略。
- 所有使用标准快照路径的会话共享该实现；tmux 合成器保留 `Viewport` 行为。

### 3.2 保留宽字符拼接信息

当前后端把宽字符占位单元转换成普通空格，窗格无法区分真实空格和折行处的前导宽字符占位。

物理快照必须增加明确的拼接元数据，至少标记行尾是否为 `LEADING_WIDE_CHAR_SPACER`。`DisplayView` 不得通过空格字符或 `wide` 猜测。拼接时删除该占位，普通宽字符占位和真实空格保持不变。

### 3.3 拼接行身份与缓存

拼接行不能只使用链首行身份。其签名必须覆盖：

- 所有成员的 `source_id` 和修订信息；
- 所有成员的内容、光标和活动输入状态；
- 是否位于回滚边界。

任一成员变化都必须使拼接行及其排版缓存失效。未变化成员继续共享 `Arc<Vec<TerminalCell>>`，不复制整段历史。

### 3.4 清屏与高水位

`max_display_cols` 只根据实际进入显示视图的行更新，只增不减。横向偏移始终限制在当前上限内。

以下情况重置高水位并归零横向偏移：

- 切回自动换行；
- 显式 `clear_buffer()`；
- 后端确认清空屏幕或回滚；
- 回滚收缩使原映射失效。

后端在快照中提供缓冲区重置代际，窗格按代际变化重置；不在 UI 中猜测输出字节或根据短行推断清屏。

## 四、DisplayView 与 DisplayMap

### 4.1 变换顺序

```text
物理快照 → 命令折叠 → 软折行拼接 → 显示快照
```

第一版只允许折叠边界对齐完整折行链。边界切入折行链时，该命令不提供折叠，避免产生不连续成员或半条逻辑行。折叠占位行没有物理坐标。

### 4.2 行映射

```rust
struct DisplayRowMap {
    /// Absolute physical line of the first chain member; folded placeholders have none.
    first_line: Option<i64>,
    /// Display column where each physical member starts.
    member_starts: SmallVec<[usize; 4]>,
}
```

要求：

- 显示坐标转物理坐标：在 `member_starts` 中定位成员，再换算物理行和列。
- 物理坐标转显示坐标：定位折行链及其成员，返回显示行和列。
- 映射覆盖前导宽字符占位被删除后的偏移，不能假定成员起点为 `成员序号 × 视口列数`。
- 映射只描述同一快照代际；切换、重排或重置后不得继续使用旧映射。
- `logical_context`、光标、活动输入状态和行签名同步转换，不能只转换 `lines`。

### 4.3 纵向滚动

- 后端 `display_offset` 继续使用物理行，搜索、命令标记和选区的物理身份不变。
- 滚轮、翻页和滚动条落点按逻辑行定位，最终对齐折行链起点。
- 不换行时清除平滑滚动余量，使用整数逻辑行偏移；自动换行保持现有平滑滚动。
- 滚动条继续按物理回滚比例显示，接受折行链长度不同造成的近似，不扫描全部历史计算逻辑行总数。

## 五、交互模型

### 5.1 普通选区

普通、语义和整行选区继续保存物理坐标，通过 `DisplayMap` 生成显示选区。复制仍从物理快照提取，保持软折行不额外插入换行。

### 5.2 块选区

不换行模式的块选区直接保存显示坐标：

- 高亮和复制读取显示快照，按每个显示行的相同列区间处理。
- 不把块选区转换成两个物理端点后再使用现有物理矩形算法。
- 切换视图或映射失效时清除块选区。
- 第一版只处理当前视口，拖出视口时钳制到边缘。

### 5.3 其他坐标消费者

统一通过 `DisplayView` 或 `DisplayMap` 接入：

- 点击、双击、三击和链接；
- 搜索范围、搜索跳转和滚动条标记；
- 命令标记、折叠控件和时间戳；
- 光标、输入法、自动建议和触发器；
- 终端鼠标上报；
- 双向文本的逻辑列与视觉列转换。

时间戳取折行链首行。搜索匹配跨物理成员时合并为连续显示范围。鼠标上报转换回物理网格坐标，不发送显示列。

### 5.4 横向跟随

只在活动输入行光标移动或刚发生键盘输入时揭示光标。普通输出、进度条和右侧提示不触发横向跟随。搜索和命令标记跳转时揭示目标列。

## 六、绘制与性能

拼接前先完成正确性，再增加横向裁剪：

- 排版只处理 `[可见首列 - 余量, 可见末列 + 余量]`，切片保留宽字符和零宽字符的所属关系。
- 背景、选区、搜索、高亮、链接和图像占位使用同一列窗口。
- 行缓存键包含拼接行签名和按余量分桶的列窗口。
- `snapshot.cols = max(视口列数, max_display_cols)`；行内容不为了高水位统一填充到该宽度。
- 不换行快照成本记为 `O(扫描物理行数 + 物化单元格数)`，不得声称只与视口行数有关。
- 绘制裁剪后的排版工作量不得随不可见右侧内容增长。

## 七、实施步骤

```text
0. 清理与基线
   - 不换行期间冻结 PTY 列数，横向 resize 只改变显示窗口，高度变化仍调整行数。
   - 保留横向滚动管线，读取显示快照；切回自动换行时恢复真实视口列数。
   - 记录自动换行和普通/长行不换行样本的帧耗时、快照耗时及缓存命中率。
   → cargo check -p oxideterm-gpui-app

1. 后端合同
   - 增加快照窗口、实际顶部、宽字符拼接元数据、重置代际。
   - 接入标准会话路径；tmux 保持原行为。
   → 后端聚焦测试

2. DisplayView
   - 先实现无折叠拼接、DisplayMap、复合签名和高水位。
   - 再迁移命令折叠，并限制折叠边界对齐完整折行链。
   → 拼接、映射、缓存及折叠测试

3. 交互
   - 普通选区、显示坐标块选区、复制、搜索、链接、时间戳、命令标记、输入法和鼠标上报。
   - 接入逻辑行滚动、横向跟随和重置行为。
   → 交互聚焦测试及 cargo check -p oxideterm-gpui-app

4. 绘制
   - 横向列窗口、缓存键和各类高亮裁剪。
   → 使用第 0 步相同样本复测

5. 收尾
   - 更新 11 个语言包，仅使用简短的“自动换行 / 不换行”含义。
   - 运行 scripts/quality/audit_i18n.py、git diff 和 git status。
```

测试由 Leo 在本地执行；仓库常规类型检查只运行 `cargo check -p oxideterm-gpui-app`。

## 八、第一版验收

| 场景 | 必须验证的结果 |
|---|---|
| 底部锚定，折行链跨历史与屏幕边界 | 链头不丢失、不重复，拼接文本与独立预期一致 |
| 顶部锚定，单条链长于视口 | 返回完整可用窗口和实际顶部，不出现空白补行或死循环 |
| 链头已超出回滚 | 明确标记不完整链，不伪造已淘汰内容 |
| 宽字符恰好在折行处 | 不多出空格；前后半格点击映射正确；真实行尾空格保留 |
| 修改折行链中间或末尾成员 | 拼接行签名变化和缓存失效，未修改成员仍复用 |
| 折叠边界切入折行链 | 不提供该折叠；合法折叠与拼接组合后的行号正确 |
| 切换开关与横向 resize | 开启时保持网格和 PTY 列数，内容不因宽度变化重排；关闭后恢复当前视口列数 |
| 横向高水位 | 无溢出时上限为 0；长行离开后保持；规定的重置事件后归零 |
| 显示坐标块选区 | 跨拼接行的高亮和复制文本按显示列对齐 |
| 跨成员搜索 | 匹配范围连续，跳转后目标和光标映射正确 |
| 不平滑的纵向滚动 | 滚轮、翻页和滚动条落点均对齐完整逻辑行 |
| alt screen、图像链和 tmux | 分别使用物理视图、物理折行链和原合成快照 |
| 超长行横向滚动 | 只排版可见列窗口，缓存键随列窗口变化，不可见内容不增加排版量 |
